# Shell Emulator

Эмулятор командной оболочки UNIX-подобной операционной системы.

## Вариант

Вариант №11.

---

# Этап 1 — REPL

На первом этапе реализованы:

1. консольный интерфейс;
2. REPL;
3. приглашение к вводу с именем VFS;
4. простой разбор команд и аргументов по пробелам;
5. команда-заглушка `ls`;
6. команда-заглушка `cd`;
7. команда `exit`;
8. обработка неизвестных команд.

---

# Этап 2 — Конфигурация

На втором этапе добавлены:

1. параметр `--vfs` для передачи пути к VFS;
2. параметр `--script` для передачи пути к стартовому скрипту;
3. отладочный вывод параметров при запуске;
4. выполнение команд из стартового скрипта;
5. поддержка комментариев в стартовом скрипте;
6. отображение команд стартового скрипта как пользовательского ввода;
7. Bash-скрипты для проверки параметров командной строки.

---

# Этап 3 — VFS

На третьем этапе добавлены:

1. загрузка виртуальной файловой системы из XML-файла;
2. хранение VFS в памяти;
3. создание VFS по умолчанию, если путь не указан;
4. поддержка двоичных данных в формате Base64;
5. минимальная VFS;
6. VFS с несколькими файлами;
7. VFS с вложенными папками не менее трех уровней;
8. автоматические тесты загрузки VFS;
9. Bash-скрипты для проверки различных вариантов VFS;
10. стартовый скрипт для проверки функциональности предыдущих этапов.

Все операции с VFS выполняются в памяти.

---

# Этап 4 — Основные команды

На четвертом этапе реализована реальная работа команд:

1. `ls` — отображение содержимого виртуальной директории;
2. `cd` — изменение текущей виртуальной директории;
3. `pwd` — отображение текущего пути;
4. `wc` — подсчет строк, слов и байт в файле;
5. `uptime` — отображение времени работы эмулятора;
6. поддержка абсолютных путей;
7. поддержка относительных путей;
8. поддержка `.` и `..`;
9. обработка ошибок;
10. автоматические тесты;
11. стартовый скрипт для проверки этапа 4.

---

# Этап 5 — Дополнительные команды

На пятом этапе реализована команда `mv`.

Команда позволяет:

1. переименовывать файлы;
2. переименовывать директории;
3. перемещать файлы между директориями;
4. перемещать объекты по абсолютным и относительным путям;
5. обрабатывать ошибки;
6. выполнять все изменения только в памяти;
7. предотвращать перемещение директории внутрь самой себя;
8. предотвращать замену уже существующего объекта.

# Запуск

Обычный запуск:

```bash
./run.sh
```

или:

```bash
python3 src/main.py
```

Запуск с VFS:

```bash
./run.sh --vfs vfs/nested.xml
```

или:

```bash
python3 src/main.py --vfs vfs/nested.xml
```

Запуск со стартовым скриптом:

```bash
./run.sh --script scripts/startup.txt
```

Запуск с VFS и стартовым скриптом:

```bash
./run.sh \
  --vfs vfs/nested.xml \
  --script scripts/startup_stage5.txt
```

# Параметры командной строки

## `--vfs`

Задает путь к XML-файлу виртуальной файловой системы.

Пример:

```bash
python3 src/main.py --vfs vfs/nested.xml
```

Если параметр не указан, создается VFS по умолчанию в памяти.

## `--script`

Задает путь к стартовому скрипту.

Пример:

```bash
python3 src/main.py --script scripts/startup.txt
```

Команды стартового скрипта выполняются последовательно.

Строки, начинающиеся с символа `#`, считаются комментариями и не выполняются.

---

# Виртуальная файловая система

Источником VFS является XML-файл.

После загрузки XML преобразуется во внутреннюю структуру данных Python, с которой работают команды эмулятора.

## Минимальная VFS

```bash
python3 src/main.py --vfs vfs/minimal.xml
```

## VFS с несколькими файлами

```bash
python3 src/main.py --vfs vfs/files.xml
```

## VFS с вложенными директориями

```bash
python3 src/main.py --vfs vfs/nested.xml
```

Структура `nested.xml`:

```text
/
└── home
    └── user
        └── documents
            └── notes.txt
```

## VFS с двоичными данными

Файл:

```text
vfs/binary.xml
```

Для хранения двоичных данных используется Base64.

# Поддерживаемые команды

## `ls`

Выводит содержимое текущей директории.

Пример:

```text
my_vfs> ls
home
```

Можно указать путь:

```text
my_vfs> ls /home
user
```

При передаче слишком большого количества аргументов выводится ошибка.

---

## `cd`

Изменяет текущую директорию.

Пример:

```text
my_vfs> cd home
```

Поддерживаются относительные пути:

```text
my_vfs> cd user/documents
```

Абсолютные пути:

```text
my_vfs> cd /home/user/documents
```

Переход на уровень выше:

```text
my_vfs> cd ..
```

При попытке перейти в несуществующую директорию выводится сообщение об ошибке.

---

## `pwd`

Показывает текущую виртуальную директорию.

Пример:

```text
my_vfs> pwd
/home/user/documents
```

В корневой директории:

```text
my_vfs> pwd
/
```

---

## `wc`

Подсчитывает:

1. количество строк;
2. количество слов;
3. количество байт.

Пример:

```text
my_vfs> wc notes.txt
1 3 14 notes.txt
```

Если файл не существует:

```text
my_vfs> wc unknown.txt
wc: file not found
```

---

## `uptime`

Показывает время работы эмулятора в формате:

```text
HH:MM:SS
```

Пример:

```text
my_vfs> uptime
00:00:03
```

---

## `mv`

Используется для перемещения и переименования файлов и директорий.

Формат:

```text
mv источник назначение
```

### Переименование файла

```text
my_vfs> mv notes.txt text.txt
```

После выполнения:

```text
my_vfs> ls
text.txt
```

### Перемещение файла

```text
my_vfs> mv /home/user/documents/text.txt /home/user
```

После этого файл находится в:

```text
/home/user/text.txt
```

### Переименование директории

```text
my_vfs> mv /home/user/documents /home/user/docs
```

### Перемещение файла в директорию

```text
my_vfs> mv /home/user/text.txt /home/user/docs
```

### Ошибка: объект не существует

```text
my_vfs> mv missing.txt new.txt
mv: no such file or directory: missing.txt
```

### Ошибка: неправильное количество аргументов

```text
my_vfs> mv only_one_argument
mv: expected two arguments
```

### Ошибка: объект назначения уже существует

```text
my_vfs> mv /home/user/docs/text.txt /home/user/docs/text.txt
mv: destination already exists: /home/user/docs/text.txt
```

### Ошибка: неправильный путь назначения

```text
my_vfs> mv /home/user/docs/text.txt /missing/text.txt
mv: invalid destination: /missing/text.txt
```

### Ошибка: перемещение директории внутрь самой себя

```text
my_vfs> mv /home/user/docs /home/user/docs
mv: cannot move directory into itself
```

Все изменения команды `mv` выполняются только во внутренней VFS в памяти.

---

## `exit`

Завершает работу эмулятора.

Пример:

```text
my_vfs> exit
```

# Основные функции программы

## `parse_cli_args`

Обрабатывает параметры командной строки:

- `--vfs`;
- `--script`.

## `parse_input`

Разделяет пользовательский ввод на имя команды и список аргументов.

## `load_vfs`

Загружает VFS из XML-файла.

Если путь не передан, создает VFS по умолчанию.

## `read_vfs_file`

Получает содержимое файла VFS.

Если файл имеет атрибут:

```text
encoding="base64"
```

его содержимое декодируется из Base64.

## `build_directory`

Рекурсивно преобразует XML-директории и файлы во внутреннюю структуру Python.

## `build_vfs`

Создает виртуальную файловую систему в памяти на основе загруженного XML.

## `create_shell_state`

Создает состояние оболочки.

В состоянии хранятся:

- VFS;
- текущая директория;
- время запуска эмулятора.

## `get_directory`

Находит виртуальную директорию по заданному пути.

## `get_node`

Находит файл или директорию в VFS по заданному пути.

## `resolve_path`

Обрабатывает абсолютные и относительные пути, а также элементы:

```text
.
..
```

## `get_parent_and_name`

Находит родительскую директорию объекта и его имя.

## `run_startup_script`

Последовательно выполняет команды из стартового скрипта.

Комментарии и пустые строки пропускаются.

## `command_ls`

Реализует команду `ls`.

## `command_cd`

Реализует команду `cd`.

## `command_pwd`

Реализует команду `pwd`.

## `command_wc`

Реализует команду `wc`.

## `command_uptime`

Реализует команду `uptime`.

## `get_source`

Получает исходный объект, его имя и родительскую директорию для команды `mv`.

## `get_destination`

Определяет директорию и имя назначения для команды `mv`.

## `contains_node`

Проверяет, находится ли один объект VFS внутри другого.

Используется для предотвращения перемещения директории внутрь самой себя.

## `command_mv`

Реализует команду `mv` для перемещения и переименования файлов и директорий.

## `execute_command`

Определяет введенную команду и вызывает соответствующую функцию.

## `repl`

Реализует основной интерактивный цикл оболочки.
